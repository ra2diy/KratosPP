# Kratos++ 开发文档

> 面向需要在 Kratos++ 上开发新功能、修复 Bug、参与共建的开发者。

## 1. 环境准备

### 1.1 依赖

- Windows 10/11；
- Visual Studio 2019（v142 工具集）或 VS Build Tools 2019；
- Git（克隆子模块）；
- 一份《尤里的复仇》游戏目录（用于复制产物与运行调试，如 `D:\Games\Yuri's Revenge\`）；
- 建议安装 VS Code + C/C++ 扩展（仓库已提供 `workspace.code-workspace` 与 `scripts/configure_vscode_cpp.bat`）。

### 1.2 获取源码

```bat
git clone --recursive https://github.com/ra2diy/KratosPP.git
cd KratosPP
```

若已克隆但子模块缺失：

```bat
git submodule update --init --recursive
```

`YRpp/` 是子模块（https://github.com/ra2diy/YRpp），提供游戏类定义与 Hook 宏，**不要提交其中的改动**。

### 1.3 工具链说明

- 解决方案：`Kratos.sln`（Kratos.vcxproj），仅 Win32/x86 平台；
- 语言标准：C++20（`stdcpp20`），启用 Modules；
- 调用约定：StdCall；禁用异常（`HAS_EXCEPTIONS=0`）、多线程静态 CRT（`/MT`）；
- 关键宏：Debug 构建定义 `DEBUG`；Release 构建定义 `IS_RELEASE_VER`。

## 2. 构建

### 2.1 脚本

| 脚本 | 作用 |
| --- | --- |
| `scripts/build_debug.bat` | Debug 构建 |
| `scripts/build_release.bat` | Release 构建 |
| `scripts/clean.bat` | 清理 `output/` 下的构建产物 |
| `scripts/copy_debug.bat` / `copy_release.bat` | 把产物复制到游戏目录并启动（路径在脚本内可改） |
| `scripts/run_yr.bat` | 复制 Release 产物到 `output/` 根并启动游戏 |
| `scripts/run_msbuild.bat` | 借助 `vswhere.exe` 定位 VS 后执行 MSBuild |
| `scripts/run_vsdevcmd.bat` | 启动 VS 开发者命令行环境 |
| `scripts/configure_vscode_cpp.bat` | 生成 VS Code C++ 配置 |

构建 Release：

```bat
scripts\build_release.bat
```

构建 Debug：

```bat
scripts\build_debug.bat
```

也可以在 Visual Studio 中直接打开 `Kratos.sln`，选择 `Release|Win32` 或 `Debug|Win32` 生成。

### 2.2 产物

- `output/Release/Kratos.dll`：Release 成品；
- `output/Debug/Kratos.dll`：Debug 版本（带控制台输出）；
- 构建后 PostBuildEvent 会调用 `scripts/copy_*`，把 DLL/PDB 复制到 `output/` 根或游戏目录。

## 3. 代码结构速览

| 目录 | 内容 | 修改频率 |
| --- | --- | --- |
| `src/Common/` | 事件、组件、INI 基础设施 | 低（基础设施） |
| `src/Extension/` | 各游戏类的扩展容器 | 中（新增扩展类） |
| `src/Ext/EffectType/` | AE 效果器 | 高（新玩法） |
| `src/Ext/StateType/` | 状态器 | 高（新玩法） |
| `src/Ext/TechnoType/` | 单位逻辑、TechnoStatus | 高 |
| `src/Ext/BulletType/` | 抛射体逻辑、弹道 | 中 |
| `src/Ext/Helper/` | 通用辅助函数 | 中 |
| `src/Hooks/` | 游戏函数钩子 | 中（接入新时机） |
| `src/Utilities/` | 通用工具（Debug/Patch/Stream 等） | 低 |

## 4. 开发约定

### 4.1 命名

- 文件：效果器 `XxxData.h`、`XxxEffect.h/.cpp`；状态器 `XxxState.h/.cpp`；数据类后缀 `Data`；
- 类：脚本类后缀 `Effect` / `State` / `Script`；扩展容器类后缀 `Ext`；
- 组件宏：`EFFECT_SCRIPT(Xxx)`（效果器）、`TECHNO_SCRIPT(Xxx)` / `OBJECT_SCRIPT(Xxx)`（组件）、`DECLARE_COMPONENT(ClassName, Base)`（通用组件）。

### 4.2 注释与文档

- 头文件对公共接口写中文 `/// @brief` 注释（仓库惯例）；
- 新增/修改 INI 标签时，同步更新 `附件包/Kratos食用说明书.ini` 或对应 `*说明书.txt`；
- 重要行为变化需在提交信息中说明。

### 4.3 代码风格

- 缩进：Tab；编码：UTF-8（VS Code 工作区配置 `files.encoding: utf8bom`，C/C++ 文件沿用 BOM 以兼容 MSVC 中文注释）；
- 命名：类型大驼峰，成员 `PascalCase`，局部变量 `camelCase`；游戏对象指针惯用 `pXxx`（如 `pTechno`）；
- 尽量使用 YRpp 类型而非裸指针/地址常量；避免魔数，地址常量写进 `DEFINE_HOOK`。

## 5. 如何添加新功能

### 5.1 添加一个普通 INI 标签（类型级）

以给 `[TechnoType]` 加一个开关为例：

1. 在 `src/Ext/TechnoType/TechnoTypeExt.h` 的 `TypeData` 中声明成员与默认值：

   ```cpp
   bool MyFeature = false;
   ```

2. 在 `Read()` 中读取：

   ```cpp
   MyFeature = reader->Get("MyFeature", MyFeature);
   ```

3. 在对应逻辑处（通常是某个 Hook 或 TechnoStatus 组件）通过 `TechnoTypeExt::ExtMap.Find(pType)` 取数据并使用。

4. 若该标签需要随存档保存，在 `TypeData` 的序列化函数中加 `stream.Process(MyFeature)`（类型级数据通常无需，实例级才需要）。

### 5.2 添加一个 AE 效果器（Effect）

以新增 `MyBuff` 效果器为例：

1. **数据类**：新建 `src/Ext/EffectType/Effect/MyBuffData.h`，继承 `EffectData`，实现 `Read`、`Serialize` 与 `EFFECT_DATA(MyBuff)` 宏；
2. **效果器脚本**：新建 `MyBuffEffect.h/.cpp`，类名 `MyBuffEffect`，继承 `EffectScript`，用 `EFFECT_SCRIPT(MyBuff)` 宏声明，实现 `Start()` / `OnUpdate()` / `Pause()` / `Recover()` 等生命周期；
3. **注册数据**：在 `src/Ext/EffectType/AttachEffectData.h` 中：
   - `#include "Effect/MyBuffData.h"`；
   - 在成员区加 `EFFECT_VAR_DEFINE(MyBuff);`；
   - 在 `ReadEffects()` 加 `EFFECT_VAR_READ(MyBuff);`；
   - 在 `GetScriptNames()` 加 `EFFECT_VAR_SCRIPT_NAME(MyBuff);`（注意顺序：Stand/Vector 等需要先于状态器创建）；
   - 在 `Serialize` 加 `EFFECT_VAR_PROCESS(MyBuff)`；
4. **加入工程**：把 `MyBuffEffect.cpp` 加入 `Kratos.vcxproj` 的 `<ClCompile>`；
5. **文档**：在 `附件包/Kratos食用说明书.ini` 的 `[AttachEffectType]` 段补充标签说明。

效果器脚本在 `AttachEffectScript` 激活时由 `AttachEffect::Attach` 按 `GetScriptNames()` 名单创建，数据通过 `GetData()` 从 `AEData.MyBuff` 获取。

### 5.3 添加一个状态器（State）

状态器与效果器结构类似，但挂在 `TechnoStatus` 下（`src/Ext/TechnoType/TechnoStatus.h`）：

1. 新建 `src/Ext/StateType/State/MyStateData.h` 与 `MyState.h/.cpp`，类名 `MyState`，继承 `StateScript`（`src/Ext/StateType/StateScript.h`）；
2. 在 `TechnoStatus.h` 中 `#include` 并持有 `MyState` 成员；
3. 在 `TechnoStatus::Setup()`（或对应初始化函数）中按标签启停状态；
4. 若状态器也可作为 AE 效果器使用，则同时在 `AttachEffectData` 中注册（效果器与状态器共用 `GetStateScriptName()` 命名）。

### 5.4 添加一个新 Hook

在 `src/Hooks/` 新建或修改文件：

```cpp
#include <Extension.h>
#include <Utilities/Macro.h>

// 0x123456 是游戏内目标函数地址，0x5 是覆盖指令长度
DEFINE_HOOK(0x123456, MyFeatureHook, 0x5)
{
    GET(SomeClass*, pObj, ESI);   // 从寄存器取参
    GET_STACK(int, value, 0x4);   // 从栈取参
    // 调用组件/事件/管理器……
    return 0; // 0 = 继续执行原函数
}
```

要点：

- 地址来自对游戏程序的分析（IDA/Ghidra），改动后必须实测；
- `DEFINE_HOOK_AGAIN` 可让同一函数绑定多个地址；
- 钩子函数保持轻量，重逻辑交给组件或事件处理器；
- 新钩子文件需加入 `Kratos.vcxproj`。

### 5.5 添加一个全局管理器

若功能是跨对象全局逻辑（如 `FireSuperManager`、`PrintTextManager`）：

1. 在 `src/Ext/Common/` 新建 `XxxManager.h/.cpp`，实现 `Clear()`（场景清理）与 `Update()`（每帧）；
2. 在 `src/Hooks/GeneralHook.cpp` 的 `GeneraHook` 构造函数中注册：

   ```cpp
   EventSystems::General.AddHandler(Events::ScenarioStartEvent, XxxManager::Clear);
   EventSystems::Logic.AddHandler(Events::LogicUpdateEvent, XxxManager::Update);
   ```

### 5.6 添加一个全新游戏对象扩展

（较少使用，仅当需要扩展新的原版类时）

1. 继承 `TypeExtension<TBase, TExt>` 或 `GOExtension<TBase, TExt>` 创建 `XxxExt.h/.cpp`；
2. 定义静态 `ExtMap`（`Container<XxxExt>`）；
3. 在 `src/Extension.cpp` 的 `ExtTypeRegistry` 模板参数列表中加入 `XxxExt`；
4. 在 `src/Hooks/` 新建对应 Hook 文件，处理 CTOR/DTOR/Save/Load 时机；
5. 加入 vcxproj。

## 6. 调试

### 6.1 Debug 构建

- Debug 构建启动时弹出"附加调试器"提示：点确定后即可用 VS 附加到 `gamemd.exe`；
- 同时创建调试控制台，`Debug::Log` 输出会显示在控制台，并写入游戏日志 `debug.log`；
- 若提示未弹出，检查是否以管理员权限运行 `gamemd.exe` 与 `syringe.exe`。

### 6.2 命令行参数

- `-SYNCLOG`：开启同步日志（记录 RNG/朝向/目标变化等，排查联机不同步）；
- `-DebugAE`（仅 Debug）：AE 调试输出；

参数通过游戏快捷方式或 `RunAres.bat` 环境传入。

### 6.3 常用调试手段

- `Debug::Log`：打日志（复用游戏日志系统写入 `debug.log`，Debug 构建额外输出到控制台）；
- `Debug::FatalErrorAndExit`：关键错误直接退出（带出口码，`SLFail=114514`）；
- `DEBUG_COMPONENT` 宏：打开组件级详细日志（`Component.h` 中定义）；
- `Common::DebugAE`：AE 相关条件日志。

## 7. 版本管理与发布

### 7.1 版本号

`src/Version.h`：

| 宏 | 含义 |
| --- | --- |
| `VERSION_MAJOR` / `MINOR` | 大/中版本，新逻辑或重大变化 |
| `VERSION_REVISION` | 小版本，Bug 修复/非硬编码 |
| `VERSION_PATCH` | Kratos 自身修复计数 |
| `BUILD_NUMBER` | 每次发布递增 |

Release 版本串形如 `Ver.0.2.2p11`；Debug 为 `Debug 0.2.2`。

### 7.2 存档兼容

- `SAVEGAME_ID` 由版本号组成，写入存档的 `InternalVersion`；
- 改变序列化布局（新增/删除字段）会破坏旧存档，发布前评估兼容性；需要兼容时在 Load 侧做版本判断。

### 7.3 发布清单

1. 更新 `src/Version.h`；
2. 更新 `附件包/Kratos食用说明书.ini`（新标签）与对应 `*说明书.txt`；
3. 构建 Release 并自测（单机 + 联机基本流程）；
4. 附带 `pips*.shp` 等资源（位于 `附件包/`）；
5. 发布包内放置 `Kratos.dll`、`Kratos.pdb`、`附件包/` 与 `LICENSE.md`。

## 8. 常见问题

**Q：编译报错找不到 YRpp 头文件？**
A：确认 `YRpp/` 子模块已初始化；IncludePath 需要 `src;YRpp;include;lib`（vcxproj 已配置）。

**Q：Debug 构建弹窗卡住？**
A：那是"附加调试器"提示；不需要调试时用 Release 构建，或先附加调试器再点确定。

**Q：新增源文件后功能不生效？**
A：检查 `Kratos.vcxproj` 是否已包含该 `.cpp`；纯头文件改动不需要。

**Q：标签写进 INI 没效果？**
A：确认标签所属段（`[AttachEffectType]` / `[TechnoType]` 等）与数据类 `Read()` 中读取的 key 完全一致（大小写不敏感但前缀要一致）；确认 `Enable` 被正确设置；查看 `debug.log` 中的解析失败提示。

1. 从 `main` 拉分支，命名建议 `feature/xxx` 或 `fix/xxx`；
2. 提交信息使用中文描述（仓库惯例），引用关联 issue/PR 编号；
3. 构建 Debug + Release 双通过；
4. 提交 PR 至 https://github.com/ra2diy/KratosPP 。
