## 1. 已确认会失同步（按修复优先级）

### P1 —— 替身位置只在**渲染回调**里更新（反汇编实证，随时可复现）—— **已修（本次）**

链路：`GScreenRenderEvent` ← `GScreenClass::DrawOnTop`(`0x4F4497`) → `Ext/ObjectType/AttachEffect.cpp:1355/1484` → `UpdateStandLocation` → `StandEffect::UpdateLocation(:550)` / `SetLocation(:564)` → `pStand->SetLocation(...)`。**非火车编组替身每帧位置更新的唯一入口就是这个渲染回调**（火车走 `:1478/1285`）。

IDA 证据（`ida_work/render_vs_logic_report.txt`）：

- `0x4F4497` 门控 `(ATTRACT_Flags&2)==0 && dword_A8EDA0==0 && GameInFocus!=0`（`0x55D878-0x55D895`）；**失焦**（`GameInFocus` 唯一写入点 `Windows_Procedure 0x7778CE`）时**联机模式（GameMode 1..4）只 `Sleep(10)` 后继续跑整帧 ⇒ 该帧 0 次渲染，而 Sort/`LogicClass::Update`(`0x55DC9E`)/校验值(`0x55DE40`) 照跑**；
- 一帧可**多次**渲染（帧尾限速器 `sub_55E160` → `0x55E271`）；
- 渲染位于 Sort(`0x55DBC8`) → Logic → hash **之前**；
- `SyncCheck_ComputeFrameHash`(`0x64DAB0`)：`hash = 3*hash + (WhatAmI + (Y/10<<16) + X/10)`，读 `[obj+0x9C]/[+0xA0]` ⇒ **X/Y 进哈希，Z(`+0xA4`) 不进**；
- 层数组**不是每帧重建**（唯一清空点 `DisplayClass_InitClear 0x4A88C0`，仅开局/重开），但**改 Y 会改 Ground 层排序**（键 `vt+0xB8`，`LayerClass_Sort 0x551A30`）⇒ 顺序敏感哈希放大分歧。

⇒ **任一端某帧整体跳过渲染（Alt-Tab 失焦即满足）⇒ 该端替身停在旧值 ⇒ 本帧校验值立刻分歧。**

修法：**首选**把这步移到逻辑期（`OnUpdate`/AI）；若坚持留在渲染期，必须同时满足：以 `Unsorted::CurrentFrame` 做**幂等键**（一帧可能 0 次也可能多次）、逻辑期**兜底更新**、**失焦时也更新**、写入是已同步状态的纯函数、**不依赖多次渲染的累加**。

**已修（本次）**：按首选方案落地 ——

- `Ext/ObjectType/AttachEffect.{h,cpp}`：新增 `AttachEffect::OnLogicUpdate`，注册在
  `Events::LogicUpdateEvent` + `EventArgsLate`（= `Hooks/GeneralHook.cpp:114` 的
  `LogicClass_Update_Late` `0x55B719`：所有对象 AI/移动之后、`0x55DE40` 校验值之前，每逻辑帧恰好一次）。
  原渲染 `BeginRender` 分支里的**替身定位块（含火车分支）**整体搬入；渲染分支只留纯视觉
  （`ae->OnGScreenRender` 与 `Info.Stack` 的显示偏移）。
- **动画 offset 一并搬**（同一渲染分支的同类隐患）：`ae->UpdateAnimOffset` → `AnimStatus::Offset`，
  它在**逻辑期**被消费成 `pAnim->SetLocation`（`Ext/AnimType/AnimStatus.cpp:209/218`）。
- `ae->IsAlive()` **只搬一处**：它带副作用（`EnableEffects`/`PauseEffects`/`Deactivate`），
  现在统一在 `AttachEffect::CheckDurationAndDisable()` 里每逻辑帧调一次，结果缓存到
  `AttachEffectScript::AliveCached`，渲染分支与逻辑分支都只读缓存（不再按渲染次数重复触发）。
- **Bullet 外推已按用户裁定去掉**：`Ext/Helper/FLH.cpp` 的 `GetRelativeLocation` 新增
  `bool predictBulletNextFrame = true`，替身定位路径（每帧定位 + 火车记录点 `MarkLocation`）
  传 `false`，取**当帧**实际坐标；其它调用者（动画定位）保持原行为。同文件 `GetRelativeDirection`
  全库无调用者，其"下一帧"外推直接删除。

### P2 —— `OnGuardCommand` / `OnStopCommand` 在**本机执行体**里改模拟 —— **已修（本次）**

根因位置：`src/Hooks/TechnoExtHook.cpp:495/496/512`（插在 `0x730D60` / `0x730EA0` 内）。

反汇编（仓库既有摘录 `ida_work/carryall_disasm.txt:94-269`）：

- `0x730D60` = `GuardCommandClass_Execute`、`0x730EA0` = `StopCommandClass_Execute`，两者体内都读 **`v_CurrentObjects`（本机选中集）**；
- 调用者只有 `0x536D00`/`0x536B80`（CommandClass 热键分发体）与 `0x6D0778`/`0x6D07D0`（`TabClass_MouseMove`，鼠标 UI）⇒ **全是单端输入路径**。

受害点（按键那端才发生）：

| 位置 | 单端副作用 |
|---|---|
| `src/Ext/TechnoType/AircraftGuard.cpp:477-483`（后续 `:290-298`/`:408-417` 用该 flag 分支） | `_onStopCommand=true; CancelAreaGuard(); State=STOP; ForceMission(Enter)` |
| `src/Ext/TechnoType/JumpjetCarryall.cpp:389-397`（`CancelMission` 在 `:37-44`） | 取消吊运，另一端继续 |
| `src/Ext/EffectType/Effect/StandEffect.cpp:931-947` | `ClearAllTarget(pStand)`（`SetTarget(nullptr)` + `QueueMission(Stop,true)`） |

原版 Guard/Stop 任务本身经 `EventClass` 广播、两端一致；**Kratos 在这些执行体里额外改的状态没有任何事件承载** ⇒ 一端返航/取消/清目标，另一端继续。

修法：**hook 可留（只应"发事件"），但不得直接改模拟**。副作用挪到两端都会跑的位置 —— (a) 引擎 `EventClass::Execute` 的同步 Idle/Stop 分支（Phobos 样板：`0x4C7512`，Idle 分支 `0x4C74CB`）；或 (b) 走本文的同步隧道，加一条消息 id + `TargetClass` 载荷，副作用放收端 `Respond`。

**已修（本次）—— 最终实现（"Stop 挂 `0x4C7512`"的中间稿已作废）**：

- **Guard 与 Stop 统一走同步隧道**：新增 `Ext/SyncEventType/TechnoScriptCommandEvent.{h,cpp}`
  （`MsgId = 2`，载荷 `EventData = { TargetClass Target; uint8_t Command; }` = **6 字节**
  ⇒ 不超过 `SmallPayloadMax(6)` ⇒ 自动走**小隧道 `0x50`**），收端复用既有
  `Hooks/SyncEventHook.cpp`（`0x4C6CC8`），**不新增任何引擎 hook**
  （原先挂在 IDLE 执行体 `0x4C7512` 的 hook 已删除）。
- **发端**（`Hooks/TechnoExtHook.cpp` 的 `0x730E56`/`0x730DEB`（Guard）、`0x730EEB`（Stop）
  三个本机执行体 hook）：不再直接改任何模拟状态，只做纯广播 ——
  ①对**被下令对象自己**投一条消息（`engineAlreadySent = true`：它在选中集里，原版命令由引擎发）；
  ②对它的每个 `StandEffect` 调 `RaiseGuardCommand()` / `RaiseStopCommand()`
  （`engineAlreadySent = false`：替身没有被引擎下令，需要收端补发原版命令）。
  也不再在本机直接 `cc->OnGuardCommand()` —— 脚本通知改由收端两端对称派发。
- **收端**（隧道 `Respond` → `TargetClass` 重解析 → 派发给该 techno 的全部 `ITechnoScript`）：
  只按 `TargetClass` 派发，不读本机选中集；`TechnoStatus::On*Command → On*Command_Stand` 在
  `!IsEngineAlreadySent() && IsCurrentInitiator()` 时**补发原版命令**
  （Guard = `GetCellAgain()` + `ClickedMission(Mission::Area_Guard, …)`；Stop = `ClickedEvent(NetworkEvents::Idle)`）
  ⇒ 原版命令恰好一条。`IsCurrentInitiator()` = 事件里的 house == 本机 `CurrentPlayer`
  （house 由 `Raise` 写成发起者）⇒ **只有发起端为真**，而发起端正是"原版按下该热键的那台机器"
  ⇒ 每台机器的行为都等价于"原版按下这个键时它该做的事"。
- **替身逐层下潜**：`StandEffect::On{Guard,Stop}Command` 只调 `Raise{Guard,Stop}Command()`
  （消息链，**不是** C++ 递归）；`ClearAllTarget`/`onStopCommand` 不再挂在本机执行体里。
- `AircraftGuard`/`JumpjetCarryall` 的单端状态改动因此改由**两端都跑**的隧道派发承载。

⚠ **残留风险（需实机确认，未改）**：

1. **OutList 队列压力**：本机 Guard/Stop 热键对被下令对象各多发 1 条 `TechnoScriptCommandEvent`
   （有 k 个替身时是 1+k 条）。`EventClass::OutList` 上限 128，且原版 `0x730E56/0x730DEB`
   在 `Add` 失败时会 **break 整个循环** ⇒ 大编队一键警戒/停止的实际上限会下降。
   若要收紧，可在发端只对"确实需要回调"的单位（有替身 / 有 `JumpjetCarryall`）投递。
2. **嵌套替身的消息扇出**：第 2 层起收端在**两端**都会走到 `StandEffect::On*Command`
   ⇒ 第 d 层投出 2^(d-1) 条消息。重复派发两端**对称**（收端补发仍被 `IsCurrentInitiator()`
   收敛为每端一次），不构成失同步，但会叠加到第 1 条的压力上。
   要收紧可在 `Raise*Command` 里加 `IsCurrentInitiator()` 门控，只让发起端投递。
3. **补发时机**：原版命令由收端在事件执行体内补发（`Networking_RespondToEvent` 循环中），
   比"原版热键在 UI 期发送"只是**同一帧内更晚**；两端一致，非失同步。
