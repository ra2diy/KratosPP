# 快捷键附加 AE —— 复现（DPKratos）+ 个体覆盖（2026-10-05）

## 1. 需求

DPKratos 有一个"按快捷键给选中单位附加 AE"的功能，但在 KratosPP 里因为**会失同步**被去掉了
（说明书里一直保留着注释版的 `[HotKeyX]` 规格）。本次要求：

1. 仿照 Phobos 的**同步做法**把它复现；
2. 原设计只有**全局配置**，需要新增**个体设置**（`[TechnoType]`）覆盖全局，
   做到"同一个快捷键对不同单位给出不同的 AE"。

## 2. 原设计（DPKratos 源码逐条对照）

源码位置：`platform/DPKratos-Lite-Source/DynamicPatcher/Projects/Extension.Kratos/`

| 文件 | 作用 |
| --- | --- |
| `TechnoType/HotKey/HotKeyAttachEffectData.cs` | 单组配置：`AttachEffects` / `AttachChances` / `Keys` + 整套 FilterData；`IsOnKey(group)`；**默认只影响自己的单位**（`AffectsOwner=yes`，Allies/Enemies/Civilian=no） |
| `TechnoType/HotKey/HotKeyAttachEffectTypeData.cs` | 一个 TechnoType 的全部组：**先读全局 `[CombatDamage]`，再用个体 section 覆盖同一索引**（`FindAndAdd` 覆盖语义） |
| `Common/Cammands/AttachEffect1..9Command.cs` | 9 个引擎命令（`Name=AttachEffect<N>`，`Group=N`），玩家在"选项→键盘"里绑键 |
| `Utilities/HotKeyHelper.cs` | `FindAndAttach(group)`：遍历**本地选中集** `ObjectClass.CurrentObjects`，按目标类型的合并配置逐组过滤后 `aeManager.Attach(...)` |

**失同步根因**：`FindAndAttach` 用 `ObjectClass.CurrentObjects`（本地选中集）+ `HouseClass.Player`（本地玩家），
在**本机立刻**改状态；AE 会改伤害/护甲/速度/武器/状态机 ⇒ 只有按键的那一端变了 ⇒ 分叉。

## 3. 移植方案：走引擎自己的同步事件队列

通道封成 Kratos 风格的 Manager `src/Ext/Common/SyncEventManager.{h,cpp}`（任何系统都能用），
通道协议与 Phobos（号段 + `QueueClass` + 三处事件长度钩子）一致，组织方式按 Kratos 本地化：

```
按键 → 遍历本地选中集 → 每个目标 SyncEventManager::Raise(号, house, 载荷)
     → 引擎随同步包广播 → 两端在 Networking::RespondToEvent(0x4C6CC8) 各执行一次 → 各自 Attach
```

| 接入点 | 地址 | 实现（`Hooks/SyncEventHook.cpp`） | 与 Phobos 同址时的安全性 |
| --- | --- | --- | --- |
| 派发 | `0x4C6CC8` | `Networking_RespondToEvent_SyncEvent` | **恒 `return 0`** ⇒ 链上 Phobos 继续执行（链式判定 ZERO） |
| 事件长度 | `0x64B6FE` | `sub_64B660_GetEventSize_SyncEvent` | 只对 `IsValidType` 的号跳走（BRANCH）；Phobos 的类型仍走它自己的分支 |
| 事件长度 | `0x64BE7D` | `sub_64BDD0_GetEventSize1_SyncEvent` | 同上 |
| 事件长度 | `0x64C30E` | `sub_64BDD0_GetEventSize2_SyncEvent` | 同上 |
| 命令注册 | `0x533066` | `CommandClassCallback_Register`（功能侧） | **恒 `return 0`** ⇒ Ares/Phobos 的命令照常注册 |

### 3.1 代码组织（隧道模型 + Kratos 的"管理器 + 事件类型文件"结构）

**引擎号当隧道，语义用我们自己的消息 id**（理由与硬约束见 §2 末）。因此：

| 位置 | 职责 |
| --- | --- |
| `src/Ext/Common/SyncEventManager.{h,cpp}` | ① **隧道表**：`0x50` 小隧道（定长 8B）、`0x51` 大隧道（定长 104B）——引擎的三处长度钩子只返回这两个常量；② **消息 id 登记表**（`enum class MsgId : uint16_t`，同一次编译内唯一，编号随版本可改）；③ 收发：`Raise(MsgId, house, 载荷)` / `Dispatch`（只接管隧道号 → 查 id）/ `GetPayload<T>` / `GetEventHouse` / `GetTunnelSize`；④ `Event`（与 `EventClass` 逐字节同构）+ `Envelope{Id}` + `Registrar` 注册器 |
| `src/Hooks/SyncEventHook.cpp` | **引擎接线**（Kratos 约定：hook 只放 `src/Hooks/`）：收端派发 `0x4C6CC8` + 网络层三处事件长度 `0x64B6FE`/`0x64BE7D`/`0x64C30E`（现在只判断"是不是隧道号"，返回定长常量），非隧道号一律 `return 0` 交回链上 |
| `src/Ext/SyncEventType/AttachEffectEvent.{h,cpp}` | **一个动作一个文件**：`Id = MsgId::AttachEffectToTarget`、载荷 `EventData`（pack(1) + `static_assert`）、发端 `Raise(组号)`（遍历本地选中集）与 `RaiseToTarget(house, target, group)`（留给后续点击/图标触发器）、收端 `Respond`（事件 house + `TargetClass` 重解析 + 过滤 + `AttachEffect::Attach`），末尾一行 `Registrar` |
| `src/Hooks/HotKeyHook.cpp` | **输入侧**：9 个 `AttachEffect1..9` 引擎命令 + 命令注册钩子，按下只调 `AttachEffectEvent::Raise(组号)` |

**新增一个动作的步骤**：在 `SyncEventManager.h` 的消息表里**追加一个 id**（不占引擎号）→ 在 `src/Ext/SyncEventType/`
下新建 `<动作名>Event.{h,cpp}`，定义载荷（≤100 字节；`#pragma pack(push,1)` + `static_assert` 钉死布局）
并写 `Respond` → 文件末尾放一个 `SyncEventManager::Registrar` → 发端调 `SyncEventManager::Raise(Id, ...)`。
**不需要动通道、不需要写引擎钩子、不需要申请号段。**

**触发方式与号的关系**：号（引擎隧道）＝稀缺资源，归**动作**所有；一个动作可以被多种触发器调用
（快捷键 / 点击 / 图标 / 触发器…），**触发器不占号**、也不该出现在动作的文件名里。

**对照 Phobos 的两个使用点**（印证它并不只服务快捷键，本模块同样面向所有系统）：

| Phobos | 触发方式 | 性质 |
| --- | --- | --- |
| `EventTypeExt::ApproachObject`(0x40) | `TechnoExt::ClickedApproachObject` ← `Hooks.BugFixes.cpp:1405`（玩家**点击**对象） | 单位指令级，典型的"交互 → 必须两端执行" |
| `EventTypeExt::TogglePlayerAutoRepair`(0x41) | `Hooks.cpp:711/720`（快捷键/侧边栏） | house 状态切换 |
| `src/Interop/EventExt.{h,cpp}` | `DEFINE_EXPORT(HRESULT, EventExt_AddEvent, EventExt*)` | 把"入队事件"暴露给**其它 DLL**；Kratos 是单一 DLL 暂不需要，日后照此加导出包装即可 |

> 别与 `Ext/Common/PaintballSyncManager` 混淆：那个 sync 是"同一端内相关对象之间的视觉状态同步"，
> 与"跨客户端同步"无关。

**事件号分段**（沿用 Phobos 源码注释给出的既成约定）：
vanilla `0x00-0x2F`、CnCNet `0x30-0x3F`、**Phobos `0x40-0x41`**、Ares `0x60-0x61` ⇒ **Kratos 只占 `0x50-0x51` 两个号**（不向外铺开，避免与其它平台/分支的既有号段交叉），
本功能占 **`0x50`**，`0x51` 预留（已登记在 `SyncEventManager.h` 的"已分配"表）。
⚠️ 内部 id 与隧道长度随版本可改（两端同一份 DLL 是前提）；唯一需要小心的是别与同进程的其它 DLL 撞号。

**事件载荷**（`SyncEventManager::Event` 与 `EventClass` 逐字节同构，111 字节，`Data` 在偏移 7）：

```cpp
struct AttachEffectEventData {
    TargetClass Target;   // 目标对象：RTTI + ID，可跨端序列化（与引擎自身的 TargetClass 事件同型）
    uint8_t     Group;    // 快捷键组号 1..9
    uint8_t     ;
};
```

**载荷里不放 AE 名字**：收端按目标的 **TechnoType ID** 重新解析 `[HotKeyX]`（全局 + 个体合并），
两端读同一份 INI ⇒ 结果一致，且事件极小。

**过滤一律以"事件里的 house"为参照**（`EventClass::HouseIndex`），**不能用本地 `HouseClass::CurrentPlayer`**
—— 否则两端会因"谁是本地玩家"而判定不同。`CanAffectHouse(pEventHouse, pTarget->Owner)` 与
原设计 `CanAffectHouse(HouseClass.Player, pTechno.Owner)` 语义等价。

**随机数**：`AttachEffect::Attach(types, chances, ...)` 的成功率走 `Bingo` → `Random::RandomDouble()`
→ **`ScenarioClass::Instance->Random`（引擎共享 RNG）** ⇒ 天然同步，无需改动。
（同文件的 `VisualRandomRanged` 用的是本地 `std::mt19937`，但它已注明"仅视觉"，不参与本功能。）

**队列上限**：`EventClass::OutList` 是 `EventList<0x80>`，**每帧 128 条**（`Count>=128` 时引擎静默丢弃）
⇒ 发端先判容量，满了就放弃本次剩余目标。

## 4. 本次新增的"个体覆盖全局"

`HotKeyAttachTypeData::Read` 逐字对齐 DPKratos：

```
读 [CombatDamage] 的 HotKey. / HotKey0. ~ HotKey127.
再用当前 section（TechnoType ID）的同名键**覆盖同一索引**
```

⇒ 全局写一套默认（例如统一给个光环），特定单位再各写各的；`Keys` 决定每组响应哪几个快捷键组。

## 5. INI 规格（说明书已同步解注）

```ini
[CombatDamage]        ; 全局
[TechnoType]          ; 个体，覆盖全局
HotKeyX.AttachEffects=AutoWeapon1,StandTest1
HotKeyX.AttachChances=100%,100%
HotKeyX.Keys=0        ; 0 或留空 = 全部；可写多个，如 1,2
; 过滤器：AffectTypes/NotAffectTypes/AffectBuilding…AffectAircraft/AffectStand/AffectInAir/
;         NotAffectMarks/OnlyAffectMarks/AffectsOwner/AffectsAllies/AffectsEnemies/AffectsCivilian
```

键位：游戏内「选项 → 键盘」绑定 **AttachEffect1 ~ AttachEffect9**（组号 1~9）。

## 6. 实测验证清单（尚未实机验证）

1. **单机**：给某单位写 `HotKey.X.AttachEffects=...`，绑键按下 ⇒ 选中单位全部拿到 AE。
2. **个体覆盖**：全局写 `HotKey0.AttachEffects=A`，某类型写 `HotKey0.AttachEffects=B`
   ⇒ 该类型按 B，其它按 A（同一按键、不同结果）。
3. **过滤器**：`AffectInAir=no` / `AffectStand=no` / `OnlyAffectMarks` / `AffectsEnemies` 各验一条。
4. **联机对拍**：两端各记 attach 日志（帧号+对象+AE），比对是否同帧同对象同结果。
5. **回归**：确认 Phobos 的事件（`ApproachObject` 0x40 / `TogglePlayerAutoRepair` 0x41）与
   命令注册**仍然生效**（验证链没被掐断）。

## 7. 注意与遗留

- **必须两端同版本 DLL**：新增事件号一旦发出，另一端若没有对应处理会各自解析出不同结果。
- 客户端可伪造事件（YR 的信任模型本就如此，单位指令也一样）；`AffectsEnemies=yes` 时
  设计上允许影响他人单位，未额外设防。
- `aeMode` 保持 `-1`（与 DPKratos 一致），未把这个功能并入 AE Modes 分组。
- 参考实现：`platform/Phobos/src/Ext/Event/`（`Body.h` 的分段约定、`Body.cpp` 的 4 个钩子）。
